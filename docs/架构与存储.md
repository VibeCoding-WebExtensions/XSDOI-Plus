# 架构与存储

## 为什么需要 background service worker

扩展里的三套存储，**content script 与 popup 不互通**：

- content script 活在站点页面的上下文里
- popup 活在 `chrome-extension://<id>/popup/` 的上下文里

两者 origin 不同，`indexedDB` 和 `navigator.storage`（OPFS）都按 origin 隔离，所以**页面里的脚本和 popup 无法直接读同一份媒体数据 / 备份文件**。`background.js` 作为扩展自身 origin 的中转站，负责：

- 媒体 Blob 的中转（AC 动画、页面背景：popup 直写 IndexedDB，页面通过消息让 worker 分片读回来，避免把几十 MB 的 base64 塞进 `sendMessage`）
- OPFS 代码备份的读写
- 消息分发

> 历史教训：`chrome.runtime.sendMessage` 用 JSON 序列化，会破坏 `ArrayBuffer`。**二进制数据必须转 base64 字符串**再传。

## 三层存储

| 存储 | 放什么 | 谁写 |
|---|---|---|
| `chrome.storage.sync` | 所有功能配置与开关 | popup 写，content script 读（`storage.onChanged` 热更新） |
| IndexedDB `ac-replacer-media` / `bg-replacer-media` | AC 动画、页面背景的媒体 Blob | popup 直写，页面经 worker 读 |
| OPFS `backups/` | 代码自动备份，文件名 `题目ID-时间戳-原因.cpp.backup` | worker 读写，popup 通过消息触发 |

`sync` 会跟着账号走，所以**不放敏感信息**。桌宠曾经把 API Key 写在 `sync` 里，功能下线后残留了很久才清理——新增配置项前先想清楚它会不会被同步出去。

## 目录职责

```
XSDOI-Plus/
├── manifest.json          MV3 配置：权限、15+ 个 content script 注入点
├── constants.js           共享常量（AC / 背景 / 打字特效等默认配置与消息名）
├── background.js          service worker：媒体中转 + OPFS 备份 + 消息分发
├── idb.js                 IndexedDB 封装
├── md-core.js             Markdown 转换纯函数（UMD，可单测）
├── content/               注入页面的脚本，一个功能一个文件
│   └── acrylic-config.js  板块美化的选择器集中列表（加选择器即生效）
├── popup/                 设置面板：每个功能一个 *-panel.js
├── assets/ fonts/ icons/  静态资源
└── docs/                  本文档目录（不参与运行）
```

## popup 面板结构

左侧竖排菜单 + 右侧设置面板，纯 HTML + 原生 JS，没有框架。

```html
<!-- popup.html -->
<div class="nav-item" data-view="pet">网页桌宠</div>
...
<section class="view" id="view-pet"> ... </section>
```

`popup.js` 里一个监听器搞定切换：点 `.nav-item` → 读 `data-view` → 找到 `#view-xxx` 切换 `.active`。**加一个新面板只要三步**：`popup.html` 加 nav-item、加 view 段落、末尾加 `<script src="xxx-panel.js">`。

### 面板内部约定

- **草稿 + 保存**：开关和数值类控件改的是草稿，点「保存配置」才写 `storage`；`storage.onChanged` 让 content script 立刻生效，**不用刷新页面**。
- **数字框**：`input` 事件只改草稿、**不回写输入框**（逐字符 clamp 会把「0.」打断成「0.20」，用户根本打不出想要的值），`change`（失焦/回车）才 clamp 并同时回写滑块与输入框。board-panel 的卡片透明度、pet-panel 的弹性/抛掷都按这套。
- 样式复用现成类：`.board-row` + `.alpha-ctl` / `.alpha-slider` / `.alpha-value`（滑块）、`.save-row` + `.save-btn`（保存）、`.as-row` / `.as-btn` / `.as-status`（按钮组与状态行）。**加面板基本不用写 CSS。**
- `.el-drawer` 抽屉里的内容整块排除美化（站点抽屉样式与玻璃层打架）。
