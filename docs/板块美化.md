# 板块美化

`content/board-beautify.js`（生成 CSS）+ `content/acrylic-config.js`（选择器列表）+ `content/bg.js`（页面背景层）。

---

## 三种玻璃外观（互斥）

用户在 popup 三选一，另有两个全局参数：

| 参数 | 含义 | 范围 |
|---|---|---|
| `mode` | 玻璃外观 | `none` 仅透明化 / `acrylic` 亚克力 / `liquid` 液态玻璃 |
| `alpha` | 玻璃层不透明度 | 0~1，默认 0.55（三模式共有）|
| `refract` | 实验性真折射 | 仅 `liquid` 生效，默认关 |

### ⚠️ 最重要的一条：只有 `liquid` 才有伪元素玻璃层

| 模式 | 「玻璃层」是什么 |
|---|---|
| `none` | 只有元素自身的半透明 `background-color`，无滤镜 |
| `acrylic` | 元素自身的半透明 `background-color` + `backdrop-filter: blur(20px) saturate(180%)` |
| `liquid` | **额外**有 `::before`（折射层）与 `::after`（高光层）两个伪元素 |

`pseudo()` 构建器包在 `if (liquid)` 分支里。所以验亚克力模式时：

```js
getComputedStyle(el, '::before').content === 'none'   // 正常！
getComputedStyle(el).isolation === 'auto'             // 正常！
```

**这是正常的，别当成「玻璃层没生成」白查一轮** —— 要验伪元素层得切到 `liquid` 模式。

## 加一个新元素

**两步，缺一不可：**

1. 在 `board-beautify.js` 的 `buildCSS` 里加一条「透明 + 白边 + 圆角」规则（每个元素的白边方式/圆角都不一样，无法统一表达）
2. 把选择器加进 `acrylic-config.js` 的 `acrylic` 数组

三个数组的含义：

| 数组 | 效果 | 什么时候用 |
|---|---|---|
| `acrylic` | 玻璃层 + 模糊 | 绝大多数顶层卡片 / 面板 |
| `glassOnly` | 只加玻璃层，不模糊 | 元素自带背景或自带伪元素（见下） |
| `blurOnly` | 只模糊，不加玻璃层 | 要保留自定义背景（渐变等） |

### 两条硬约束

1. **玻璃层底色规则必须留在 `buildCSS` 末尾**。它靠「写在后面」覆盖掉前面逐元素的 `background-color` 规则；新规则写在它之前会被后面的 `!important` 反杀。
2. **元素自带 `::before` 时只能进 `glassOnly`**。进 `acrylic` 会让液态玻璃的折射层去抢同一个伪元素，而站点 scoped 规则特异性更高 → 两边各赢一半 → **双圈错位**。真实例子：`.fortune-seal`（首页运势签）自带内圈 `::before`。

## 压过站点样式的四条规律

扩展的 `<style>` 是 `document_start` 插进 `head` 的，**排在站点样式表之前**。所以「同特异性 + 同重要性」时**站点赢**。每加一条规则前先在站点 CSS 里搜一遍：

1. **站点规则无 `!important`** → 扩展的普通类选择器 + `!important` 即可。
2. **站点用「非 scoped + `!important`」写同一属性** → 与扩展的 `!important` 重要性打平，**靠源码顺序决胜，站点在后 → 站点赢**。对策：提升特异性（`html .x`；要压过站点自身的 `html.theme-dark` 就写 `html.theme-dark.theme-dark`）**并自己把该属性写一遍**。
   真实例子：`.streak-chip`。
3. **站点把颜色写在内联 `style` 上**（JS 动态写入）→ **任何普通选择器都压不过，带 id 也不行**，只有作者样式表里的 `!important` 能压过内联。
   真实例子：侧边栏 `#nav .el-menu-item`（`style="color:rgb(168,176,194)"`）。
4. **`!important` 会无差别压掉站点的「状态」规则**。`!important` 战胜普通声明，**与特异性无关**。给基础类写 `background-color: … !important` 时，`.is-checked` / `:hover` 这类**无 `!important`** 的状态规则会被一起压死。
   - 要保留状态色：把选择器收窄成 `:not(.状态类)`。
     真实例子：`.el-switch__core` 曾把选中态品牌蓝压成灰色，开关开/关看不出区别 → 改成 `.el-switch:not(.is-checked) .el-switch__core`。
   - 要保留 hover：**自己补一条更高特异性的 `:hover` / `:focus`**，用半透明底色 + 提亮边框，**文字色别写**（让它继续跟随站点的品牌色）。
     真实例子：竞赛排行榜的「榜单设置」/「比赛设置」按钮从加上这个功能起就一直没有悬停反馈。

### 描边别跟随状态色

站点选中态规则里 `border-color` 往往与 `background` **同色**（`.el-switch.is-checked .el-switch__core` 亮 `#409eff`、暗 `var(--brand-600)`）。跟着它写 = 选中态又没有边框了。**描边两态保持一致的中性色。**

### 有填充的控件不要套「亚克力白边」

`el-switch` 这种自带填充的控件，站点默认边框（`#dcdfe6`）与填充同色，而全局的 `rgba(255,255,255,0.5)` 白边在亮色下又与填充/卡片同色 → **两种写法都等于「没有边框」**。

有填充的控件用**中性描边**：亮 `rgba(0,0,0,0.12)` / 暗 `rgba(255,255,255,0.22)`。

### 改边框别用简写

站点常用 `border-left-color` 承载状态语义色，简写会把它一起冲掉。只改需要的那几边。真实例子：`countdown-card` 的左侧 3px 状态色条（正常/警告/危险三色），只能改上/右/下三边。

## 暗色主题的特异性陷阱

站点常这么写变量：亮色定义在 `:root`（0,1,0），暗色在 `html.theme-dark` **重定义同名变量**（0,1,1）。

扩展若也用 `html.theme-dark`(0,1,1) → 与站点那条**特异性完全相同 + 站点样式在后 → 站点赢**。于是**亮色正常、暗色静默失效**。

对策：写 `html.theme-dark.theme-dark`(0,2,1)。

> **所以主题相关改动必须明暗两套都验。** 只验亮色会漏掉一整类 bug。真实例子：自定义字体颜色，暗色下一直没生效，因为默认值和站点值恰好近似，所以没人发现。

## 液态玻璃的八条硬性禁忌

1. **折射走 `backdrop-filter: url(#id)`，绝不走 `filter: url()`**。`filter` 会栅格化整个层叠上下文，把卡片内的图标/文字卷进 `feDisplacementMap` → 图标拉伸。
2. **折射层 `inset:0`，绝不负 inset 外扩**。用 `-16px` + `clip-path`「补」边界，真实站点上相邻卡片的折射层会重叠 → 整页发白。
3. **伪元素逐项 `map` 挂载**（`pseudo()` / `darkPseudo()`）。用 `selLine(sels).replace(' {','::before {')` 只会挂到列表最后一项，其余 70+ 元素全无玻璃层。
4. **构建器返回行数组时 `push(...)` 必须带展开运算符**。否则拼出 `sel {,  -webkit-backdrop-filter...}`，浏览器整条忽略。
5. **玻璃层压在内容之下**：`::before` `z-index:-2`、`::after` `-1`，不能 0/1。否则 backdrop 含元素自身文字 → 文字错位重影（`.cc-card` hover 时临时成层叠上下文，「消失」得诡异，极难定位）。
6. **负 z-index 必须配父元素 `isolation: isolate`** 收容，否则玻璃层会沉到祖先背景后 → 整个消失。**别用 `z-index:0` 收容**（会 `!important` 压掉 Element UI 内联 style 上的气泡 z-index）。`isolation` 同时不创建包含块，不影响绝对定位子元素。
7. **绝不覆盖站点已定位元素的 `position`**：`#nav`/`.el-backtop`（`fixed`）、`.el-select-dropdown`/`.el-dropdown-menu`（`absolute`）、`.ct-lib`（`sticky`）。`#nav` 改成 `relative` 后会掉出文档流被 `.full-height` 盖住 → **侧边栏菜单点击全被吞**。
8. 参数：置换最大位移 `REFRACT_SCALE = 8`（4 = 可感知无伪影，≥12 = 四角撕裂成菱形）。位移图 = data URI SVG，水平 `#000→#f00→#000` 驱 x、垂直 `#000→#0f0→#000` 驱 y，`mix-blend-mode:screen`，中心黑 = 位移 0。滤镜宿主是隐藏 `<svg width=0 height=0>`。

**顺带**：滑块的玻璃小球与进度条随模式联动（亚克力 = 内部毛玻璃、液态玻璃 = 内部折射、仅透明化 = 无滤镜），拖拽/悬停时 `scale(1.25)`。

## 验证方法

视觉改动**不能只靠读 computed**，也不能只靠肉眼看截图。按这个顺序来：

1. **一个模式一个 HTML 文档**。绝不能把多模式的 CSS 堆进同一页对比 —— 各模式选择器特异性完全相同，**最后一份 CSS 赢下所有元素**，会误判扩展全坏。
2. **受控复现页**：最小 DOM + 从站点 CSS 摘录的原样规则 + 用 `vm` 跑扩展脚本真实生成 CSS 再注入。
   - ⚠️ **文档顺序必须还原生产：站点样式排在扩展样式之后**。把站点样式写前面会把「同特异性靠源码顺序决胜」那一整类冲突全部掩盖，得出乐观的假结论。
   - 摘录站点规则时**变量定义必须一起摘全**，漏了 `--c-xxx` 会让颜色回落成继承值，看起来像扩展失效。
   - 站点 `<style scoped>` 编译成 `.cls[data-v-xxxx]`，DOM 上必须真带 `data-v-xxxx` 属性。
   - 纯内联无外链的页面放纯 ASCII 路径（`E:/_ghost/`），避开 `file://` + 中文路径被判 404。
3. **用 `vm` 跑真实脚本生成 CSS，别手抄**。手抄必漏，而且抄错了看不出来。
4. **断言要读伪元素**：`getComputedStyle(el, '::before')` 能给出 `zIndex` / `inset` / `backgroundImage` / `backdropFilter` / `boxShadow`。
5. **「看不看得见」要让像素说话**：computed 只能证明规则生效，证明不了肉眼可辨。截图后用**纯 Python 标准库（zlib + struct）手写 PNG 解码**，沿穿过目标的一行逐像素取 RGB，**按亮度分桶**打 ASCII 图，和理论值对账。
   - 本机 Chrome 截图带**次像素抗锯齿**，单像素 R/G/B 会互相串扰（能差 100+），判断必须按**亮度**而不是按通道。
   - 找扫描行别用「不同颜色最多」当判据，会命中文字行而不是目标行。
   - 裁剪两张 PNG 做 A/B 对比**不可靠**：变体高度可能差 1px，同一裁剪落在不同亚像素 → 像重影/光晕，纯是错位假象。
6. **FAIL 先怀疑断言，别先改代码**。断言脚本自己很容易骗人。

> 一次性验证脚本用完就删，别留在项目里。
